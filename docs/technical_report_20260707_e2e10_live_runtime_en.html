2. Root Cause

Faulty hot-path call chain: high-frequency live endpoint -> _require_latest_pixel_world_access_code() -> _canonical_pixel_world_record() -> _latest_pixel_world_records() -> scan/materialize public package catalog.
Observation Evidence Interpretation
Direct store profiling was fast create_session ~70ms; heartbeat, state, and action roughly 1-2ms The core live store was not the bottleneck.
Route validation was slow _require_latest_pixel_world_access_code() cost roughly 7.4-8.0s per call Every live request paid full catalog validation cost.
WebSocket handshake timed out Before the fix, 10/10 WS handshakes exceeded timeout The WS route used the same slow canonical-world guard before accepting.
No artificial delay matched the symptom No business-path sleep explained the repeated 16-90s pattern The regression was validation architecture, not pacing logic.

3. Fixes Applied

File Change Runtime effect
macro_ui/routes/pixel_api.py Added _require_pixel_live_access_code() and switched live session, state, action, heartbeat, release, and file routes to it. REST live endpoints no longer scan the full catalog.
macro_ui/routes/websocket.py Switched WebSocket route validation to the lightweight live access-code check. WebSocket handshakes can accept promptly.
macro_ui/serve_macro_ui.py Made uvicorn reload opt-in via --reload or AGORA_MACRO_UI_RELOAD=1, and narrowed reload directories when enabled. Load tests avoid dev reloader overhead and package-tree watching.
scripts/pixel_live_load_test.py WebSocket state_delta is treated as transport success; movement rejection remains recorded as accepted=false. The stress summary no longer misclassifies collision or rule rejection as backend failure.

9. Recommendations

Priority Recommendation Reason
P0 Keep full latest/public catalog validation off live hot paths. This was the direct root cause of the latency regression.
P1 Run a 10-browser Firefox canvas E2E test next. API and WebSocket latency are healthy again; browser rendering and asset hydration are the remaining realistic concurrency surface.
P1 Consider compact session-create and WebSocket hello payloads later. The initial payload is still around 600KB. It no longer breaks latency, but it is worth optimizing.
P2 Add a local-mode cleanup fallback to the load harness. If HTTP release times out, use PixelLiveStore.release_session() to avoid active test users.
